# A01:2021 — Broken Access Control (кратко)
## Корневая причина — одна
**Решение о доступе принимается по данным, которые контролирует клиент, — или не принимается вообще.**
Проверка должна быть: (1) на сервере, (2) по серверным данным, (3) для каждого запроса.
---
## Проявление → причина → решение
| Проявление | Причина | Решение |
|---|---|---|
| Доступ по умолчанию открыт | нет deny by default | запрещено всё, что не разрешено явно |
| Подмена `id`, `role`, `tenant` в URL/теле | сервер верит параметру | брать из сессии / БД, не из запроса |
| Force browsing (`/admin` руками) | на маршруте нет проверки | авторизация на каждом маршруте (middleware) |
| **IDOR** — чужой объект по ID | нет проверки владельца записи | `obj.owner_id == user.id` перед отдачей |
| API без проверок на POST/PUT/DELETE | проверяли только GET | проверять **все** методы |
| Повышение привилегий через JWT | доверие к claim'ам клиента | подпись + серверная сессия, короткий TTL |
| CORS `*` с credentials | мисконфиг | allowlist origin'ов |
| Скрытые кнопки/ссылки как «защита» | security by obscurity | серверная проверка, 403 |
| `.git`, бэкапы, листинг каталогов | мисконфиг веб-сервера | запрет листинга, вынести из webroot |
---
## Пять фиксов по приоритету
1. **Deny by default** — доступ только по явному разрешению.
2. **Единый механизм авторизации** (middleware/декоратор), а не проверки в каждом обработчике по памяти.
3. **Объектная проверка владельца** — не «пользователь валиден», а «этот объект его».
4. **Не доверять клиенту**: роль, тенант, id — из серверного состояния; cookie — только id сессии.
5. **Логировать 403 + rate limit** — чтобы атаку было видно.
---
## Одна фраза для интервью
> Контроль доступа работает только тогда, когда он реализован в серверном коде и опирается на серверные данные; всё, что пришло от клиента — включая скрытые поля, cookie и JWT — может быть изменено.
---
## Для тебя как QA
OWASP прямо говорит: *«Разработчики и специалисты по контролю качества должны включать функциональный контроль доступа в модульные и интеграционные тесты»*.
Практически это значит: тест, который для каждого эндпоинта проверяет
`401` без сессии, `403` с чужой ролью и `403` при доступе к чужому объекту.

## A03 — Injection

- **Что это своими словами:** пользовательский ввод и SQL оказались в одной строке;
  ввод меняет структуру запроса. Позволяет не только читать данные, но и менять/удалять
  их, обходить аутентификацию и выполнять команды ОС.

- **Как выглядит в запросе:**
  ?category=' OR 1=1--                          → обход фильтра
  ?category=' UNION SELECT username,password FROM users--
  ?category=Gifts' ORDER BY 1--                 → определение числа колонок перед UNION

- **Как выглядит в коде:**
  text(f"SELECT * FROM products WHERE category = '{category}'")
  cursor.execute("... WHERE id = " + user_id)

- **Как обнаружить:**
  - одиночная кавычка → 500/ошибка SQL/изменение выдачи
  - SAST: конкатенация/f-string/format в SQL, execute() без параметров
  - разница ответов на `1 AND 1=1` vs `1 AND 1=2`

- **Как исправить (по приоритету):**

  1. **Параметры вместо склейки.**
     Значение не вставляется в текст SQL — оно летит отдельно, драйвер сам его
     подставит и заэкранирует.
     Было:  text(f"SELECT ... WHERE category = '{category}'")
     Стало: text("SELECT ... WHERE category = :cat"), {"cat": category}

  2. **ORM вместо ручного SQL.**
     Пусть SQL собирает библиотека из условий, а не ты из строк.
     Было:  text(f"SELECT * FROM products WHERE category = '{category}'")
     Стало: select(Product).where(Product.category == category)
     Важно: ORM не спасает, если внутри text() / raw() / extra() остаётся склейка.

  3. **Список разрешённых имён (allowlist) для идентификаторов.**
     Имя колонки, имя таблицы, направление сортировки параметром передать нельзя.
     Их можно только сверить со списком и подставить из него.
     sort = sort if sort in {"name", "price"} else "name"

  4. **Проверка формата входных данных.**
     Длина, допустимые символы, набор значений. Это дополнительный слой:
     он сужает возможности атакующего, но дыру не закрывает — валидная строка
     "' OR 1=1--" проходит любую проверку формата.

  5. **Минимальные права пользователя БД.**
     Если инъекция всё-таки случится, аккаунт БД должен уметь только то, что нужно
     приложению: без доступа к таблице users, без DROP, без чтения чужих схем.

  6. **Не показывать SQL-ошибки пользователю.**
     Текст ошибки подсказывает атакующему структуру БД (имена таблиц, колонок).
     Пользователю — общее сообщение, подробности — в лог.
