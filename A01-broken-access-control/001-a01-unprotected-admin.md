# Broken Access Control — Unprotected admin functionality

| | |
|---|---|
| **Лаба** | [Unprotected admin functionality](https://portswigger.net/web-security/access-control/lab-unprotected-admin-functionality) |
| **Уровень** | Apprentice |
| **OWASP** | A01:2021 — Broken Access Control |
| **CWE** | CWE-862: Missing Authorization |
| **Дата** | 2026-11-07 |
| **Инструменты** | браузер, curl |

---

## 1. Цель

Получить доступ к панели администратора и удалить пользователя `carlos`.

---

## 2. Уязвимость

Маршрут `/administrator-panel` не проверяет ни аутентификацию, ни роль:
любой посетитель получает полный доступ к админке.

Путь к панели раскрыт в `robots.txt` — это **способ обнаружения**, а не сама
причина уязвимости. Причина в том, что сервер не проверяет права.

```
GET /robots.txt → Disallow: /administrator-panel
```

---

## 3. Обнаружение

1. Открыл `https://<lab>/robots.txt` → нашёл `Disallow: /administrator-panel`.
2. Перешёл по этому пути без логина → ответ `200`, отрисовалась админка.
3. Редиректа на форму входа не было → значит, серверной проверки роли нет.

---

## 4. Эксплуатация

```bash
curl -i https://<lab>/administrator-panel
# HTTP/1.1 200 OK → панель отдана без аутентификации
```

В панели нажал «Delete» напротив `carlos` → лаба решена.

![Админ-панель без авторизации](img/001-admin-panel.png)

---

## 5. Почему работает

Защита строилась на «путь неочевиден» (security by obscurity), а не на проверке
прав. Сервер не смотрит, кто пришёл: маршрут существует и отдаёт контент любому.

Это **vertical privilege escalation**: пользователь без роли администратора
выполняет административное действие.

---

## 6. Влияние

**В этой лабе:** удаление пользователей, полный контроль над админ-функциями.

**В общем случае:** чтение и изменение любых данных (PII, заказы, платежи),
создание новых администраторов, блокировка сервиса.

---

## 7. Исправление (по приоритету)

1. **Серверная проверка роли на каждом админ-маршруте** — deny by default.
2. **Единый механизм авторизации** (middleware/декоратор), а не отдельные
   проверки в каждом обработчике по памяти.
3. **Не полагаться на скрытые ссылки и неочевидные URL** — это не контроль.
4. **Убрать админ-пути из `robots.txt`** — defense in depth: путь всё равно
   найдётся сканером или словарём.
5. **Логировать и алертить** обращения к админке без прав (403).

---

## 8. Как это выглядит в коде

### Плохо

```python
@app.get("/administrator-panel")
def admin_panel():
    return render_template("admin.html")   # проверки нет вообще
```

### Хорошо

```python
def require_admin(user=Depends(current_user)):
    if user.role != "admin":
        raise HTTPException(status_code=403)

@app.get("/administrator-panel", dependencies=[Depends(require_admin)])
def admin_panel():
    return render_template("admin.html")
```

---

## 9. Вывод

Защита «через неочевидность» не работает: путь находится через `robots.txt`,
JS в исходниках страницы или перебором. Единственный реальный контроль —
проверка прав на сервере для каждого запроса.
