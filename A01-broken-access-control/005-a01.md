---

## 1. Цель

Получить пароль администратора, затем удалить пользователя `carlos`.

---

## 2. Уязвимость

Страница аккаунта открывается по адресу `/my-account?id=wiener`. Сервер берёт `id` из URL и отдаёт данные пользователя, **не проверяя**, что этот `id` принадлежит текущей сессии. Кроме того, пароль пользователя передаётся в HTML-коде страницы в открытом виде, хотя в браузере он скрыт за маской (`type="password"`).

Если заменить `wiener` на `administrator`, приложение показывает страницу администратора, и в исходном коде HTML можно найти его пароль в открытом виде.

---

## 3. Эксплуатация

1. Логинимся как `wiener:peter`.
2. Переходим в личный кабинет: `/my-account?id=wiener`.
3. Открываем исходный код страницы (Ctrl+U) или перехватываем ответ в Burp.
4. Видим поле: `<input type="password" name="password" value="[пароль_wiener]">`. Маска в браузере не скрывает значение из HTML.
5. Меняем в URL `wiener` на `administrator`: `/my-account?id=administrator`.
6. В исходном коде страницы администратора находим его пароль в том же поле `value="..."`.
7. Выходим, логинимся как `administrator` с найденным паролем.
8. Переходим в админ-панель и удаляем пользователя `carlos`.

---

## 4. Результат

Пароль администратора получен, пользователь `carlos` удалён, лаба решена.

## 5. Почему работает

## 5. Почему работает

Сервер доверяет параметру `id` из URL и использует его для поиска пользователя в базе данных. При этом пароль пользователя передаётся в HTML-коде страницы аккаунта в открытом виде (в атрибуте `value`).

**Уязвимый код (Python/Flask):**

```python
from flask import Flask, request, render_template, session

app = Flask(__name__)

@app.route("/my-account")
def my_account():
    # Сервер берёт id из URL и не проверяет, кому он принадлежит
    user_id = request.args.get("id")
    user = db.get_user(user_id)
    return render_template("account.html", user=user)
html
<!-- account.html -->
<input type="password" name="password" value="{{ user.password }}">
Правильно (Python/Flask):

python
from flask import Flask, request, render_template, session, abort

app = Flask(__name__)

@app.route("/my-account")
def my_account():
    # Сервер берёт id из сессии, а не из URL
    user_id = session.get("user_id")
    if not user_id:
        abort(401)
    user = db.get_user(user_id)
    return render_template("account.html", user=user)
html
<!-- account.html: пароль не передаётся в HTML вообще -->
<!-- Если нужна смена пароля — требовать ввод старого пароля -->
Если id в URL нужен (например, для админов), сервер должен проверять, что запрошенный id совпадает с текущим пользователем, или что текущий пользователь — админ:

python
@app.route("/my-account")
def my_account():
    requested_id = request.args.get("id")
    current_user_id = session.get("user_id")

    if requested_id != current_user_id and not is_admin(current_user_id):
        abort(403)

    user = db.get_user(requested_id)
    return render_template("account.html", user=user)
```

## 6. Влияние

**В этой лабе:** доступ к аккаунту администратора и его паролю в открытом виде.

**В реальной системе:** полная компрометация аккаунта администратора, доступ к админ-функциям, удаление или изменение данных, дальнейшее развитие атаки.

---

## 7. Исправление

1. **Не доверять `id` из URL.** Брать идентификатор текущего пользователя из сессии (подписанной куки/токена).
2. **Не передавать пароль в HTML.** Пароль не должен отображаться на странице аккаунта даже в замаскированном виде. Если нужна смена пароля — требовать ввода старого пароля, а не показывать его.
3. **Проверять авторизацию на сервере.** Если `id` остаётся в URL — сверять его с текущим пользователем или проверять роль админа.

---

## 8. Вывод

Нельзя доверять параметру `id` из URL при доступе к объектам. Маска `type="password"` не скрывает пароль из исходного кода страницы. Сервер должен проверять, что запрошенный объект принадлежит текущему пользователю, и не передавать чувствительные данные в HTML.
